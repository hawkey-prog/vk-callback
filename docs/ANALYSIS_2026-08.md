# VK Callback — модерация сообщества

Проект для модерации VK-сообщества: удаление и бан пользователей через VK API.

## Архитектура

```
index.html (GitHub Pages) → Cloudflare Worker (index.js) → Flask сервер (app.py, 89.108.78.99:5001)
```

- **Frontend** (`index.html`): страница авторизации VK ID, получает код авторизации
- **Cloudflare Worker** (`index.js`): проксирует запрос на сервер
- **Backend** (`app.py`, Flask + gunicorn): обменивает код на токен, вызывает VK API

## VK API — типы ключей доступа

Источник: [dev.vk.ru](https://dev.vk.ru/ru/api/access-token/getting-started)

| Тип ключа | От чьего имени | Срок действия | Где использовать |
|-----------|---------------|---------------|-----------------|
| Сервисный | Приложение | Не ограничен | Сервер |
| Пользователя | Пользователь | **1 час** | Клиент или сервер |
| Сообщества | Сообщество | Не ограничен | Клиент или сервер |

Ключ передаётся в заголовке: `Authorization: Bearer <TOKEN>`

### Ключ доступа пользователя

[Документация](https://dev.vk.ru/ru/api/access-token/user-token)

- Срок действия: **1 час**
- Способы получения:
  - **VK Bridge** (`VKWebAppGetAuthToken`) — для мини-приложений и игр, клиентская часть
  - **VK ID SDK** — для любого приложения/сайта, клиентская или серверная часть
  - **HTTP-запрос без SDK** — альтернатива VK ID SDK
- Права доступа:
  - **Базовые** (сразу): имя, фамилия, фото, пол, дата рождения, почта
  - **Расширенные** (подтверждение бизнеса): номер телефона
  - **Индивидуальные** (через devsupport@corp.vk.com): например, доступ к `groups`
- Для серверных запросов использовать ключ, полученный через **сервис авторизации VK ID** (не через VK Bridge)

### Ключ доступа сообщества

[Документация](https://dev.vk.ru/ru/api/access-token/community-token)

- Срок действия: **не ограничен**
- Получить может только **администратор** сообщества
- Способы получения:
  - **Настройки сообщества**: Управление → Дополнительно → Работа с API → Ключи доступа → Создать ключ
  - **OAuth ВКонтакте (Authorization Code Flow)** — серверная часть
  - **OAuth ВКонтакте (Implicit Flow)** — клиентская часть
  - **VK Bridge** (`VKWebAppGetCommunityToken`) — для мини-приложений
- Можно отозвать в настройках сообщества

### Устаревшие способы (нельзя использовать)

- Authorization Code Flow для ключа пользователя — **отключён с 25 июня 2024**
- Implicit Flow для ключа пользователя — **отключён с 25 июня 2024**
- Client Credentials Flow для сервисного ключа — **отключён с 17 октября 2022**
- Бессрочные ключи, выпущенные раньше, продолжают работать

## VK API — методы проекта

### groups.removeUser
Удаляет пользователя из сообщества. Требует **ключ доступа пользователя** со scope `groups`.

### groups.banUser
Банит пользователя в сообществе. Требует **ключ доступа пользователя** со scope `groups`.

> ⚠️ Ключ сообщества НЕ подходит для этих методов — возвращается `error_code: 27` (метод недоступен с group auth).

# Разбор тупика и решение (август 2026)

## Главный вывод: ждать ответа devsupport бессмысленно

Письмо в `devsupport@corp.vk.com` с просьбой «добавить право `groups` приложению
54634256» не будет удовлетворено не потому, что его не рассмотрели, а потому что
**запрошено то, чего в VK ID не существует**.

VK ID — это сервис **аутентификации**, а не авторизации к VK API. Актуальный
[список доступов VK ID](https://id.vk.ru/about/business/go/docs/ru/vkid/latest/vk-id/connection/work-with-user-info/scopes)
содержит ровно три значения:

| scope | что даёт |
|---|---|
| `vkid.personal_info` | имя, фамилия, пол, фото, дата рождения |
| `email` | почта |
| `phone` | телефон (после подтверждения бизнес-профиля) |

`groups` в этом списке нет и не появится — это scope другой системы (классический
VK API), которая живёт отдельно от VK ID.

### Чем это подтверждается

1. **Формат токена.** `id.vk.ru/oauth2/auth` выдаёт токены вида `vk2.a.*`. Это
   VK ID-токены, предназначенные только для получения данных профиля. Вызов любого
   «настоящего» метода VK API ими даёт `error_code: 1051 — Method is not available
   for this profile type`. Ровно это мы и получили на `groups.banUser`.
   Тот же симптом независимо описан в
   [postiz-app#1408](https://github.com/gitroomhq/postiz-app/issues/1408) (апрель 2026)
   для `wall.post` — вывод там тот же: `vk2.a.*` несовместимы с методами VK API.
2. **`error_code: 15 / subcode 1133`** на `groups.removeUser` — «не может быть вызван
   с текущими scope». Никакой scope из трёх доступных этого не откроет.
3. **`error_code: 27`** на ключе сообщества — жёсткий запрет на стороне VK:
   `groups.removeUser` / `groups.banUser` в принципе недоступны с group auth.
   Обхода нет.
4. **`Security Error`** при попытке дернуть `oauth.vk.com/authorize` с `client_id=54634256` —
   старый OAuth не принимает приложения, созданные в кабинете VK ID. Обратной
   совместимости нет.

Итого все четыре двери, в которые стучались, закрыты не по недосмотру, а by design.

## Что закрыто окончательно

| путь | статус |
|---|---|
| VK ID + scope `groups` | невозможно: такого scope в VK ID нет |
| Ключ сообщества (`manage`) | `error 27`, методы недоступны с group auth |
| Implicit Flow / Authorization Code Flow для user-токена | отключены VK 25 июня 2024 |
| Создать Standalone-приложение | тип убран из кабинета |
| Чужие client_id (VK Admin, `6121396` и т.п.) | `application is blocked` |
| Бессрочный токен через `offline` | в новых флоу не выдаётся, `expires_in` всегда 3600 |

## Единственный оставшийся легальный путь: VK Mini App + VK Bridge

`groups` остался самообслуживаемым scope ровно в одном месте — в событии
[`VKWebAppGetAuthToken`](https://dev.vk.ru/ru/bridge/VKWebAppGetAuthToken) для
мини-приложений. Актуальный список scope этого события:

```
friends, photos, video, stories, pages, status,
messages, wall, docs, groups, stats, group_messages, market
```

`groups` в нём есть, и одобрение поддержки для него **не требуется** — права
подтверждает сам пользователь в диалоге согласия. Токен приходит классического
формата (не `vk2.a.*`), то есть пригоден для методов VK API.

### Как это выглядит на практике

1. Создать **мини-приложение** (не VK ID-приложение) на `dev.vk.com` →
   «Создать приложение» → тип «Мини-приложение». Модерация нужна только для
   публичного запуска; для себя достаточно режима разработчика и админского доступа.
2. Frontend мини-приложения (можно сделать из нынешнего `index.html`) вызывает:
   ```js
   const r = await bridge.send('VKWebAppGetAuthToken', {
     app_id: <ID мини-приложения>,
     scope: 'groups'
   });
   // r.access_token — классический user-токен с правами groups
   ```
   Важно: `window.location` страницы обязан совпадать с URL из настроек приложения.
3. Токен уходит на нынешний Flask-сервер тем же `POST /vk/exchange-code`
   (переименовать в `/vk/set-token`) — вся серверная часть, nginx, systemd и
   эндпоинты `/vk/remove-user`, `/vk/ban-user` остаются как есть.

### Два риска, которые надо снять до переписывания кода

**Риск 1 — срок жизни.** Токен живёт 1 час, `offline` в списке scope Bridge нет.
Автономный бот через час встанет. Варианты:

- **A. Вызывать методы прямо из мини-приложения** (штатный, разрешённый VK способ).
  Сервер хранит очередь user_id на удаление, мини-приложение при открытии забирает
  очередь и выполняет `groups.removeUser` клиентски. Минус: нужен человек,
  открывающий приложение.
- **B. Отдавать токен на сервер** и работать им час, обновляя при следующем
  открытии. Можно свести к рутине «открыть приложение раз в час» на закреплённой
  вкладке.

**Риск 2 — серверное использование.** [Документация VK](https://dev.vk.ru/ru/api/access-token/user-token)
прямо пишет, что ключ из VK Bridge предназначен для клиентских запросов
мини-приложения, а для серверных надо брать ключ из VK ID. Технически токен
классический и с сервера работать должен, но это **не проверено** и VK может
ужесточить проверку в любой момент. Вариант A выше от этого риска свободен.

### Порядок проверки (10 минут, до всякого рефакторинга)

1. Создать мини-приложение, получить его `app_id`.
2. Открыть его у себя, вызвать `VKWebAppGetAuthToken` со `scope: 'groups'`,
   посмотреть, что вернулось в `access_token` и `scope`.
3. Сразу из мини-приложения дернуть `groups.removeUser` на связке
   `group_id=236838246`, `user_id=277162801` — это ответ на риск 1 (работает ли
   scope вообще).
4. Тот же токен положить в `/opt/vk-bot/tokens.json` и повторить curl-проверку с
   сервера — это ответ на риск 2 (пускает ли VK токен Bridge с сервера).

Результат шагов 3 и 4 определяет архитектуру: оба «да» → остаётся нынешняя схема,
меняется только способ добычи токена. Шаг 3 «да», шаг 4 «нет» → вариант A.

## Что делать с письмом в поддержку

Нынешняя формулировка («добавьте scope `groups` приложению VK ID») запрашивает
несуществующую вещь — отвечать на неё нечего, отсюда и молчание. Если писать
повторно, то по делу:

> Задача — автоматизированная модерация собственного сообщества 236838246
> (удаление и блокировка участников). Методы `groups.removeUser` / `groups.banUser`
> недоступны: с ключом сообщества — `error 27`, с токеном VK ID — `error 15/1051`.
> Подскажите поддерживаемый способ вызова этих методов от имени администратора
> сообщества в текущей платформе.

Такой вопрос отвечаем: либо назовут мини-приложение, либо назовут условия
индивидуального доступа.
