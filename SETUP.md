# Сборка и запуск

VK выдал приложению **54634256** индивидуальный доступ к `groups`. Значит,
работает исходная схема: сервер получает токен через VK ID, сам его обновляет
и сам вызывает методы. Мини-приложение и ручная очередь остаются запасным
путём, в норме они не нужны.

Шаги идут по порядку, каждый следующий опирается на предыдущий. После каждого
есть проверка — если она не прошла, дальше идти бессмысленно.

> `server/.env.example` устарел и не обновлялся (файл закрыт правилом доступа
> в рабочей среде). Актуальный состав `.env` — в этапе 2 ниже.

## Этап 1. Сертификат сервера — начинать отсюда

Страница авторизации живёт на GitHub Pages и обращается к вашему серверу из
браузера. Если сертификат невалиден, браузер оборвёт запрос молча, и ни один
следующий этап не заработает.

Замер снаружи **19.09.2026**: на 443 по-прежнему отдаётся **самоподписанный**
сертификат — пустые Subject и Issuer, ошибка `RemoteCertificateNameMismatch`.
Порт 80 теперь отвечает (301 на https), в августе он молчал. Это важно:
значит, Let's Encrypt сможет подтвердить домен и выпуск сертификата пройдёт.

Прошлые проверки проблему не ловили, потому что шли через `curl -k`, а этот
флаг ровно её и прячет. Заодно это объясняет, почему любой запрос по http
выглядит как ошибка TLS: 301 уводит на https, где сертификат невалиден.

Проверить состояние можно прямо с домашней машины:

```powershell
pwsh -File server\check_tls.ps1
```

Смотрим, что на сервере:

```bash
certbot certificates
nginx -T 2>/dev/null | grep -nE 'server_name|ssl_certificate|listen'
ss -tlnp | grep -E ':(80|443)'
```

Что искать:

- `certbot certificates` пуст или просрочен — настоящего сертификата нет;
- в конфиге фигурирует `vk-bot.crt` или `snakeoil` — nginx указывает не на тот
  файл, правится одна строка `ssl_certificate`;
- порт 80 не слушается — Let's Encrypt не сможет подтвердить домен.

Выпуск или перевыпуск:

```bash
ufw allow 80/tcp; ufw allow 443/tcp
certbot --nginx -d 89-108-78-99.sslip.io
nginx -t && systemctl reload nginx
```

**Проверка — с домашнего компьютера и без `-k`:**

```bash
curl https://89-108-78-99.sslip.io/
```

Ответ `VK moderator is running` — можно идти дальше. Ошибка сертификата —
дальше идти нельзя.

Запасной путь, если с сертификатом не выходит: развернуть прокси из папки
`worker/` на Cloudflare, он даёт валидный HTTPS. Тогда в поле «Адрес сервера»
на странице вписывается адрес воркера. Порт 80 до сервера при этом всё равно
нужен.

## Этап 2. Сервер

### 2.1. Код

Репозиторий публичный, файл берётся прямо с GitHub:

```bash
systemctl stop vk-bot
cd /opt/vk-bot
cp app.py app.py.bak-$(date +%F)
curl -fsSL -o app.py https://raw.githubusercontent.com/hawkey-prog/vk-callback/main/server/app.py
./venv/bin/pip install -q flask requests python-dotenv gunicorn
grep -c exchange-code app.py
```

Последнее число больше нуля — скачалась версия с обменом кода VK ID.

### 2.2. Настройки

Пишем `.env` одной командой, чтобы секреты не переносить руками:

```bash
cat > /opt/vk-bot/.env <<EOF
STATE_FILE=/opt/vk-bot/state.json
ADMIN_SECRET=$(python3 -c "import secrets;print(secrets.token_hex(24))")
BOT_SECRET=$(python3 -c "import secrets;print(secrets.token_hex(24))")
VK_CLIENT_ID=54634256
VK_REDIRECT_URI=https://hawkey-prog.github.io/vk-callback/index.html
VK_TOKEN_URL=https://id.vk.ru/oauth2/auth
VK_GROUP_ID=239099649
ALLOWED_ORIGIN=https://hawkey-prog.github.io
VK_API_VERSION=5.199
EOF
chmod 600 /opt/vk-bot/.env
cat /opt/vk-bot/.env
```

Из напечатанного забираем:

- `ADMIN_SECRET` — вводится на странице авторизации, блок 1;
- `BOT_SECRET` — в BotHelp, заголовок `X-Bot-Secret`.

`VK_REDIRECT_URI` обязан совпадать с доверенным Redirect URL в настройках
приложения 54634256 символ в символ — VK сверяет его при обмене кода.

`BOT_SECRET` обязателен: раньше `/vk/remove-user` был открыт всему интернету
без проверки, то есть чистить сообщество мог кто угодно.

### 2.3. Служба

```bash
curl -fsSL -o /etc/systemd/system/vk-bot.service https://raw.githubusercontent.com/hawkey-prog/vk-callback/main/server/vk-bot.service
systemctl daemon-reload && systemctl enable --now vk-bot && sleep 2 && curl -s http://127.0.0.1:5001/
```

Ответ `VK moderator is running` — сервер жив.

`-w 1 --threads 4` в юните не случайность: очередь лежит в одном файле, и два
процесса gunicorn начнут выдавать одни и те же задания дважды.

## Этап 3. Авторизация — главная проверка

Открываем <https://hawkey-prog.github.io/vk-callback/> в обычном браузере,
где вы вошли во ВКонтакте под администратором сообществ.

1. **Блок 1**: адрес сервера `https://89-108-78-99.sslip.io`, ключ доступа —
   `ADMIN_SECRET` из `.env`. Нажать «Сохранить».
2. **Блок 2**: «Войти через VK ID».
3. VK покажет форму разрешений — согласиться.

Страница запрашивает `scope=groups` и передаёт `prompt=consent`. Второе важно:
без него VK может молча переиспользовать ваше прежнее согласие, выданное до
того, как приложению открыли доступ, и вернуть только `vkid.personal_info`.

После возврата страница сама обменяет код на токен и покажет результат:

- **«Право groups получено»** — доступ работает, идём дальше;
- **«groups не выдан»** со списком того, что вернул VK — доступ к приложению
  ещё не активирован либо форма согласия его не показала. Эту строку нужно
  отправить в поддержку, она отвечает на их вопрос буквально.

## Этап 4. Проверка удаления

**Блок 3**: «Загрузить список» — появятся сообщества, где вы администратор.
Выбрать нужное.

**Блок 4**: ввести ID пользователя и нажать «Удалить».

- «Готово, ответ VK: 1» — задача решена, схема работает целиком;
- «Сервер не смог выполнить сам и поставил в очередь» — с текстом причины;
- ошибка VK — присылайте текст, он же пишется в журнал внизу страницы.

## Этап 5. BotHelp

Внешний запрос из бота:

```
POST https://89-108-78-99.sslip.io/vk/remove-user
Content-Type: application/json
X-Bot-Secret: <BOT_SECRET из .env>

{"user_id": {{vk_user_id}}}
```

Для блокировки — то же самое на `/vk/ban-user`. `group_id` передавать не нужно,
берётся из `VK_GROUP_ID`; если сообществ несколько — добавьте его в тело.

| Код | Значение | Что делать боту |
|---|---|---|
| 200 | удалён сразу | ничего |
| 202 | принято в очередь | ничего |
| 400 | ошибка VK, текст в теле | показать |
| 403 | неверный `X-Bot-Secret` | починить заголовок |
| 409 | токена нет, нужна авторизация | сообщить вам |

Токен живёт час, но сервер обновляет его сам по `refresh_token`. Заново
авторизоваться нужно, только если обновление перестало проходить — тогда
запросы начнут отвечать `202` с причиной, а блок 2 страницы покажет, что не так.

Нужны, только если основной перестал работать.

страницы. Там же можно отметить сделанное вручную, чтобы человек не всплыл
дважды.

`denied for non-standalone applications`, поэтому как основной не годится.
