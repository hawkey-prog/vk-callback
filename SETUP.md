## Этап 1. Мини-приложение в кабинете VK

Нужно **мини-приложение**, а не приложение VK ID. Это разные сущности в разных
кабинетах, и `groups` даёт только мини-приложение.

1. Откройте <https://dev.vk.com/> и войдите тем же аккаунтом, под которым вы
   администратор сообщества 236838246.
2. «Мои приложения» → «Создать приложение».
3. Тип — **«Мини-приложение» (VK Mini Apps)**. Название любое, например
   «Модератор». Категория — любая.
4. После создания в адресе приложения будет `vk.com/app<ЦИФРЫ>`.
   Эти цифры — ваш `APP_ID`, запишите их.

> **Если типа «Мини-приложение» в списке нет, а предлагают только «Веб / Android / iOS»** —
> значит вы попали в кабинет VK ID (`id.vk.ru`), это тот же кабинет, где лежит
> приложение 54634256, и мини-приложение там не создать. Пришлите скриншот
> страницы создания — по нему найдём вход в кабинет мини-приложений. Дальше по
> инструкции идти не надо, весь остальной код от этого не зависит.

### Настройки приложения

В настройках мини-приложения заполните адрес, откуда VK будет его открывать:

| Поле | Значение |
|---|---|
| Адрес приложения (Web) | `https://hawkey-prog.github.io/vk-callback/` |
| Мобильный адрес, если есть отдельное поле | то же самое |

Адрес обязан совпадать с тем, откуда запрашивается токен, — VK Bridge сверяет
`window.location`. Слэш на конце важен.

Публиковать и проходить модерацию **не нужно**: как автор вы открываете своё
приложение и без публикации.

## Этап 3. Главная проверка: даёт ли VK право `groups`

Это тот самый вопрос, ради которого всё затевалось. Проверяется за минуту и
**до** возни с сервером.

1. В открытом `vk.com/app<APP_ID>` нажмите **«Выдать права groups»**.
2. VK покажет окно согласия — подтвердите.

Что должно произойти: статус станет «токен есть», а в блоке 2 выпадающий список
заполнится вашими сообществами.

- **Список сообществ заполнился** → право `groups` выдано, тупик пройден.
  Идите дальше.
- **«VK не выдал право groups. Выдано: …»** → в этом кабинете `groups` для
  мини-приложений тоже закрыли. Пришлите текст ошибки целиком, это меняет план.

3. Выберите сообщество, в блоке 3 введите тестовый `user_id` (например
   `277162801`) и нажмите **«Удалить»**.

Ответ `1` — метод отработал, задача решена. Любая ошибка VK — присылайте её
текстом, он выводится на экран и пишется в лог внизу страницы.

## Этап 4. Сервер

Сервер уже развёрнут, python и venv на месте — нужно обновить код, завести
секреты и починить сертификат. Всё выполняется по SSH под root на `89.108.78.99`.

### 4.1. Обновить код

Репозиторий публичный, поэтому файл берётся прямо с GitHub — так он всегда
свежий и ничего не нужно копировать руками:

```bash
systemctl stop vk-bot
cd /opt/vk-bot
cp app.py app.py.bak-$(date +%F)
curl -fsSL -o app.py https://raw.githubusercontent.com/hawkey-prog/vk-callback/main/server/app.py
./venv/bin/pip install -q flask requests python-dotenv gunicorn
grep -c queue/list app.py
```

Последняя команда должна напечатать число больше нуля — это признак, что
скачалась новая версия с эндпоинтом для списка модерации.

Старый `tokens.json` не трогаем: новая версия его не читает, но пусть лежит.

### 4.2. Секреты

Генерируем и записываем `.env` одной командой, чтобы секреты не пришлось
переносить руками:

```bash
cat > /opt/vk-bot/.env <<EOF
STATE_FILE=/opt/vk-bot/state.json
ADMIN_SECRET=$(python3 -c "import secrets;print(secrets.token_hex(24))")
BOT_SECRET=$(python3 -c "import secrets;print(secrets.token_hex(24))")
VK_GROUP_ID=236838246
ALLOWED_ORIGIN=https://hawkey-prog.github.io
VK_API_VERSION=5.199
EOF
chmod 600 /opt/vk-bot/.env
cat /opt/vk-bot/.env
```

Из напечатанного забираем:

- `ADMIN_SECRET` — вводится в мини-приложении, блок 4, поле «Ключ доступа»;
- `BOT_SECRET` — в BotHelp, заголовок `X-Bot-Secret`.

`BOT_SECRET` обязателен: раньше `/vk/remove-user` был открыт всему интернету
без всякой проверки — то есть чистить ваше сообщество мог кто угодно.

### 4.3. Служба

```bash
curl -fsSL -o /etc/systemd/system/vk-bot.service \
  https://raw.githubusercontent.com/hawkey-prog/vk-callback/main/server/vk-bot.service
systemctl daemon-reload
systemctl enable --now vk-bot
systemctl status vk-bot --no-pager -l | head -20
curl -s http://127.0.0.1:5001/
```

Последняя команда обязана ответить `VK moderator is running`. Если да —
приложение живо, и дальше речь только о том, как до него добраться снаружи.

Обратите внимание на `-w 1 --threads 4` в юните. Раньше стояло `-w 2`, но
очередь лежит в одном файле, и два процесса начнут выдавать одни и те же
задания дважды.

### 4.4. Сертификат — сейчас это главная проблема

Проверка снаружи (13.08.2026) показала: порт 443 открыт, TLS отвечает, но
сертификат **самоподписанный** — пустые поля Subject и Issuer, ошибка
`RemoteCertificateNameMismatch`. Порт 80 снаружи не отвечает вовсе.

Браузер такой сертификат не примет, а значит мини-приложение до сервера
не достучится: запрос упадёт молча, ещё до того как сервер его увидит.
Прошлые проверки этого не показывали, потому что делались с `curl -k`,
а этот флаг ровно такую проблему и прячет.

Смотрим, что происходит:

```bash
certbot certificates
nginx -T 2>/dev/null | grep -nE 'server_name|ssl_certificate|listen'
ss -tlnp | grep -E ':(80|443)'
ufw status 2>/dev/null || iptables -L -n | head -20
```

Что искать в выводе:

- **`certbot certificates` пуст или сертификат просрочен** — настоящего
  сертификата нет, его надо выпустить (см. ниже);
- **в `nginx -T` есть `vk-bot.crt` или `snakeoil`** — nginx отдаёт
  самоподписанный; надо переключить `ssl_certificate` на файлы Let's Encrypt;
- **порт 80 не слушается или закрыт файрволом** — Let's Encrypt не сможет
  подтвердить домен, выпуск сертификата не пройдёт.

Выпуск или перевыпуск (порт 80 к этому моменту должен быть открыт):

```bash
ufw allow 80/tcp; ufw allow 443/tcp     # если ufw включён
certbot --nginx -d 89-108-78-99.sslip.io
nginx -t && systemctl reload nginx
```

Если certbot отказывается, а разбираться некогда — есть обход: развернуть
прокси из папки `worker/` на Cloudflare. Он даёт заведомо валидный HTTPS,
а до сервера идёт по обычному HTTP. Тогда в мини-приложении в поле «Адрес
сервера» вписывается адрес воркера вместо `89-108-78-99.sslip.io`. Условие:
до сервера должен доходить HTTP снаружи — то есть порт 80 всё равно нужен.

### 4.5. Проверка — с домашнего компьютера, а не с сервера

Проверять надо оттуда же, откуда пойдёт браузер, и **без `-k`**:

```bash
curl https://89-108-78-99.sslip.io/
```

- `VK moderator is running` — сервер доступен, сертификат в порядке,
  можно переходить к этапу 5;
- ошибка сертификата — вернуться к 4.4, мини-приложение пока не заработает.

Затем — что видит приложение:

```bash
curl -H "X-Admin-Secret: <ADMIN_SECRET>" https://89-108-78-99.sslip.io/vk/status
```

Ответ — JSON с полями `has_token`, `queue_pending`, `server_side_ok`.
`403` означает, что секрет не совпал с тем, что в `.env`.

## Этап 6. BotHelp

Внешний запрос из бота:

```
POST https://89-108-78-99.sslip.io/vk/remove-user
Content-Type: application/json
X-Bot-Secret: <BOT_SECRET из .env>

{"user_id": {{vk_user_id}}}
```

Для блокировки — тот же запрос на `/vk/ban-user`. `group_id` передавать не надо,
он берётся из `VK_GROUP_ID`; если сообществ несколько — добавьте его в тело.

Коды ответа:

| Код | Значение | Что делать боту |
|---|---|---|
| 200 | удалён сразу | ничего |
| 202 | принято в очередь, выполнится при открытой вкладке | ничего |
| 400 | ошибка VK, текст в теле | показать |
| 403 | неверный `X-Bot-Secret` | починить заголовок |
| 409 | токена нет, откройте приложение | сообщить вам |

200 и 202 оба означают «принято», бот их различать не обязан.

## Этап 7. Ручная модерация по списку

Пока VK не открыл доступ к методам, удаление делается руками, а приложение
берёт на себя всё остальное: кого, за что и не забыли ли.

1. Откройте `vk.com/app54720386`, блок **«Список на модерацию»**,
   нажмите «Обновить список».
2. В списке — все, кого бот поставил в очередь: имя со ссылкой на страницу
   человека, действие (удалить или заблокировать), причина и время.
3. По ссылке открываете человека и удаляете его из сообщества штатными
   средствами VK.
4. Возвращаетесь и жмёте **«Сделано»** — строка уходит из очереди в историю.
   Решили не трогать — **«Пропустить»**, он тоже уйдёт, но останется помеченным
   как невыполненный.

Кнопка «Открыть сообщество» ведёт на вашу группу, чтобы не искать её отдельно.

Бот при этом работает как раньше: шлёт запросы, сервер их принимает и копит.
Меняется только последний шаг — вместо API его делает человек.

## Этап 8. Автоматическая обработка — когда VK откроет доступ

Блок 6 в приложении. Сейчас кнопка не даст результата: `groups.removeUser`
и `groups.ban` отклоняются для не-standalone приложений.

Как только доступ появится — нажать «Запустить обработку». Пока вкладка
открыта, приложение раз в 10 секунд забирает задания и выполняет их само,
а токен продлевает каждые 45 минут без диалога согласия. Закрыли вкладку —
задания не теряются, копятся и выполнятся при следующем открытии.
Накопленное за время ожидания разберётся тем же механизмом, без переделок.

Состояние очереди:

```bash
curl -H "X-Admin-Secret: <ADMIN_SECRET>" https://89-108-78-99.sslip.io/vk/status
```
