# Модерация VK-сообщества

Удаление и блокировка участников сообщества по внешнему запросу от бота BotHelp.

Порядок сборки — в [SETUP.md](SETUP.md). Разбор старого тупика и доказательства,
почему сделано именно так, — в [docs/ANALYSIS_2026-08.md](docs/ANALYSIS_2026-08.md).

## Как это работает

```
BotHelp ──POST──► Flask (89.108.78.99)
                    │
                    ├─ токен принимают с сервера ──► api.vk.com          ← 1 запрос, ответ сразу
                    │
                    └─ не принимают ──► очередь ──► мини-приложение ──► VK Bridge ──► api.vk.com
                                                    (вкладка vk.com/app<ID>)
```

Сервер сам определяет, каким путём идти: при получении токена он пробует вызвать
`groups.get` от своего имени. Получилось — работает напрямую и вкладка не нужна.
Не получилось — складывает задания в очередь, а исполняет их мини-приложение,
где токен заведомо рабочий. Если VK отберёт доступ на ходу, сервер переключится
в очередь сам, не потеряв задание.

## Почему через мини-приложение

Прошлая версия брала токен через VK ID (`id.vk.ru`) и упиралась в то, что
методов управления сообществом там нет в принципе: VK ID — сервис входа, его
токены формата `vk2.a.*` не работают с VK API, а весь его список прав это
`vkid.personal_info`, `email`, `phone`. Права `groups` там не существует, поэтому
письмо в devsupport и осталось без ответа — просили несуществующее.

`groups` осталось доступно без согласований ровно в одном месте — в событии
[`VKWebAppGetAuthToken`](https://dev.vk.ru/ru/bridge/VKWebAppGetAuthToken)
мини-приложений: право подтверждает сам пользователь в диалоге, и токен приходит
классический, пригодный для методов API.

Подробности с ссылками и разбором каждого кода ошибки (15, 27, 1051, Security
Error) — в [docs/ANALYSIS_2026-08.md](docs/ANALYSIS_2026-08.md).

## Эндпоинты

Для бота (заголовок `X-Bot-Secret`):

| Метод | Назначение |
|---|---|
| `POST /vk/remove-user` | `{"user_id": 123}` — удалить из сообщества |
| `POST /vk/ban-user` | `{"user_id": 123}` — заблокировать |

Для мини-приложения (заголовок `X-Admin-Secret`):

| Метод | Назначение |
|---|---|
| `POST /vk/token` | принять токен, определить режим работы |
| `GET /vk/queue` | забрать задания |
| `POST /vk/queue/ack` | подтвердить выполнение |
| `GET /vk/status` | токен, режим, очередь, последние 20 операций |

## Статус на 14 августа 2026: упёрлись в ограничение VK

Мини-приложение работает и **право `groups` VK выдаёт** — это проверено вживую.
Но сам вызов метода отклонён:

```
API(groups.removeUser): Access denied: no access to call this method.
Permission to perform this action is denied for non-standalone applications
```

То есть `groups` получен, а метод разрешён только **standalone-приложениям**.
Мини-приложение таковым не является, и сменить это в настройках нельзя.

### Почему это конец всех самостоятельных путей

| путь | чем закрыт |
|---|---|
| Standalone-приложение | тип убран из кабинета, создать нельзя |
| Токен VK Admin | отключён VK **13 апреля 2026**, старые токены аннулированы |
| VK ID | scope `groups` не существует, токены `vk2.a.*` не работают с API |
| Ключ сообщества | `error 27`; по схеме VK методы принимают только user-токен |
| Мини-приложение | `groups` выдаётся, но метод запрещён не-standalone приложениям |

Дата отключения VK Admin объясняет исходную поломку: бот работал именно на таком
токене, в апреле его отключили — отсюда «в апреле работало, в мае перестало».

Официальная схема VK ([VKCOM/vk-api-schema](https://github.com/VKCOM/vk-api-schema),
`groups/methods.json`) подтверждает, что записывающие методы принимают только
пользовательский ключ:

| метод | допустимые типы ключа |
|---|---|
| `groups.removeUser` | `user` |
| `groups.ban` / `groups.unban` | `user` |
| `groups.getBanned` | `user`, `group` |
| `groups.getMembers` | `user`, `group`, `service` |

Читать список участников и забаненных сообщество может, а удалять и банить — нет.

### Чего делать нельзя

В обсуждениях как обход предлагают токены Kate Mobile, vfeed, Prizma. **Этого
делать не нужно:** с мая 2026 за такие токены VK выдаёт блокировки аккаунтов,
и сроки растут. Ставить под удар личный аккаунт администратора ради удаления
подписчиков — цена несопоставимая.

### Что остаётся

Единственный законный путь — индивидуальное разрешение от VK. Текст обращения
подготовлен в [docs/SUPPORT_REQUEST.md](docs/SUPPORT_REQUEST.md): в отличие от
прошлого письма, он называет конкретный метод, конкретную ошибку и конкретный
вопрос, на который есть ответ.

Код при этом готов целиком: как только доступ появится, работать начнёт сразу —
менять ничего не придётся.

## Что проверено, а что нет

Проверено локально: вся логика сервера — очередь, выдача заданий без дублей,
возврат брошенных заданий, оба режима, автооткат при отказе VK, защита
эндпоинтов, CORS (`server/test_app.py`); поведение фронтенда во всех сценариях
отказа (`test_frontend.js`).

Проверено вживую: мини-приложение открывается, мост работает, `groups` выдаётся,
метод отклоняется по причине выше.

Проверено вживую и `groups.ban` — отказ дословно тот же. Это подтверждает, что
запрет висит на приложении, а не на отдельном методе: любой пишущий метод раздела
`groups` будет отклонён так же, пока приложение не станет standalone.

## Открытый тикет в поддержке

13 августа 2026 VK ответил на первое обращение: просят ждать. Тикет живой,
поэтому новые данные нужно досылать в тот же тред, а не заводить новое письмо —
текст дополнения в [docs/SUPPORT_REQUEST.md](docs/SUPPORT_REQUEST.md).

Сильная сторона позиции: право `groups` уже выдано штатным способом, метод
вызван, отказ пришёл с формулировкой про тип приложения. Это не «дайте нам
что-нибудь», а «мы прошли весь ваш путь и упёрлись вот в это».

## Ограничения

- Токен живёт час. В режиме очереди приложение продлевает его само при открытой
  вкладке; в прямом режиме сервер проработает час после последней отправки токена
  и дальше начнёт складывать задания в очередь.
- `-w 1` в systemd не случайно: очередь лежит в одном JSON-файле, несколько
  процессов gunicorn начнут выдавать одни и те же задания дважды.
- `groups.removeUser` работает для групп; для публичной страницы участника
  удалить нельзя, там только блокировка (`groups.ban`).
