# Модерация VK-сообществ

Удаление и блокировка участников по внешнему запросу от бота BotHelp.

Порядок сборки — в [SETUP.md](SETUP.md). История тупика с VK ID и разбор всех
кодов ошибок — в [docs/ANALYSIS_2026-08.md](docs/ANALYSIS_2026-08.md).

## Как это работает

```
BotHelp ──POST──► Flask (89.108.78.99) ──► api.vk.com
                    │                        ▲
                    │   токен VK ID          │
                    │   обновляется сам      │
                    └── не вышло ──► очередь ─┘
                                     (страница или app.html)
```

Токен берётся через VK ID с PKCE: страница авторизации получает код, сервер
меняет его на пару access + refresh и дальше обновляет сам. Access живёт час,
refresh — дольше, поэтому в норме входить руками нужно один раз.

Если вызов почему-то не прошёл, задание не теряется: сервер кладёт его в
очередь, и её можно разобрать вручную на той же странице.

## Про доступ к `groups`

Методы `groups.removeUser` и `groups.ban` требуют пользовательский ключ с
правом `groups`. Это право **не выдаётся самостоятельно** — только
индивидуально, по обращению в `devsupport@corp.vk.com`.

Для приложения **54634256** такой доступ выдан (сентябрь 2026). Поддержка
отдельно предупредила: чтобы право попало и в токен, его нужно запросить
на шаге авторизации. Поэтому страница передаёт `scope=groups` и, что важнее,
`prompt=consent` — без него VK может переиспользовать согласие, выданное
до открытия доступа, и вернуть только `vkid.personal_info`.

Первое, что показывает страница после входа, — какой `scope` реально пришёл.
Это единственный надёжный признак, что всё получилось.

## Эндпоинты

Для бота — заголовок `X-Bot-Secret` (админский секрет тоже подходит):

| Метод | Назначение |
|---|---|
| `POST /vk/remove-user` | `{"user_id": 123}` — удалить из сообщества |
| `POST /vk/ban-user` | `{"user_id": 123}` — заблокировать |

Для страницы — заголовок `X-Admin-Secret`:

| Метод | Назначение |
|---|---|
| `POST /vk/exchange-code` | обмен кода VK ID на токены. **Без секрета** — вызывается из браузера, защищён одноразовостью кода и PKCE |
| `POST /vk/refresh` | обновить пару токенов вручную |
| `GET /vk/status` | токен, `scope`, срок, режим, очередь, последние 20 операций |
| `GET /vk/groups` | сообщества, которыми управляет владелец токена |
| `GET /vk/queue/list` | посмотреть очередь, ничего не захватывая |
| `GET /vk/queue` | забрать задания в работу (для `app.html`) |
| `POST /vk/queue/ack` | подтвердить выполнение или пропуск |
| `POST /vk/token` | принять готовый токен от мини-приложения |

## Что проверено, а что нет

Проверено локально, с заглушкой вместо VK: обмен кода, распознавание `scope`,
автообновление просроченного токена, повтор при коде 5, поведение когда
обновить нечем, очередь без дублей и потерь, оба режима, защита эндпоинтов,
CORS (`server/test_app.py`). Плюс мини-приложение (`test_frontend.js`).

Не проверено, потому что требует живого VK и рабочего сервера: вернёт ли VK
`groups` в токене после выдачи доступа и пройдёт ли `groups.removeUser`.
Это этапы 3 и 4 инструкции.

**Отдельно не проверено и блокирует всё остальное:** сертификат сервера.
На 13.08.2026 на 443 висел самоподписанный, а браузер такой не примет.
Это этап 1.

## Ограничения

- `groups.removeUser` работает для групп; у публичной страницы участника
  удалить нельзя, там только блокировка (`groups.ban`).
- `-w 1` в systemd обязателен: очередь в одном JSON-файле, несколько процессов
  начнут выдавать одни и те же задания дважды.
- Обновление токена инвалидирует прежнюю пару — держать копии старых
  токенов бессмысленно.
- `server/.env.example` устарел: файл закрыт правилом доступа в рабочей среде
  и не обновлялся. Актуальный состав `.env` — в [SETUP.md](SETUP.md), этап 2.
